# 菜谱原料采用确定性优先的低 token 清洗

菜谱原料清洗不把全部33,930种写法或340,791次提及发送给模型。字符、数量、用途、受控品牌、刀工、生熟、别名、组合、替代、调味料/油排除和烹饪辅料分流先由版本化确定性规则执行；模型只接收清洗后仍无法唯一判断、达到频次阈值且按基础身份再次聚合的队列。模型只生成身份候选，不能判断犬食安全、选择营养来源或直接发布。结果按输入、规则和模型版本缓存，低置信度项保持隔离。

该方案以有限覆盖换取可重复性、可审计性和稳定成本。规则能够处理的新写法不会消耗 token；长尾低频项可以延后而不阻断高频基础食材扩库。
