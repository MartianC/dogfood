## 1. 文档定位与适用优先级

本文只冻结下一阶段的目标导航、页面树、页面职责、入口关系和关键用户状态，不描述当前代码已经完成的能力，也不指定最终页面路径、视觉稿或实现结构。

发生文档冲突时按以下边界处理：

- 导航模型、页面职责和入口归属以本文为目标态事实来源。
- 共享本餐的档案门禁、草稿恢复、菜单选择、评估、保存和历史快照规则，继续以 [`每日“和狗狗一起吃”单餐创建与记录 PRD`](./2026-07-26-shared-meal-checkin-prd.md) 为准。
- `docs/基础功能.md`、`docs/微信小程序设计文档.md` 和 `docs/小程序架构设计.md` 在主线 `DOC1.1` 完成前继续描述当前实现；其中“三 Tab”是迁移基线，不是目标态。
- 最终 canonical 路径、旧深链映射、服务依赖和回滚方式由后续 `P0.2` 冻结，本文不提前假定目录落点。

## 2. 冻结原则

1. 底部导航采用“首页、记录、狗狗、我的”四个目的地，并在中间提供“记一顿”动作。
2. 中央动作不是第五个 Tab，不拥有选中态，也不代表一个长期停留的页面。
3. 狗狗档案从“我的”移入独立“狗狗”目的地；“我的”只承担账号与设置类低频能力。
4. 首页只使用当前已经存在的数据组织今日任务，不依赖体重历史、疫苗或驱虫能力。
5. 记录页在主线阶段继续只回看本餐记录，不等待后续统一时间轴。
6. 旧公共狗饭食谱、制作周期和批量清单保留兼容访问与历史数据，但不再进入主导航或新用户主路径。
7. 选狗、选菜单、编辑本餐、档案编辑和记录详情是任务型子页面，不显示一级 TabBar 或额外悬浮“记一顿”。

## 3. 目标页面树

```text
小程序
├─ 一级目的地（常驻底部导航）
│  ├─ 首页：今日概览与下一步
│  ├─ 记录：本餐历史回看
│  ├─ 狗狗：档案中心
│  │  └─ 单狗概览
│  └─ 我的：账号与设置
├─ 中央动作（常驻底部导航，不是目的地）
│  └─ 记一顿：进入统一本餐启动/恢复流程
├─ 当前任务型子页面
│  ├─ 登录与建档往返
│  ├─ 选择本次狗狗
│  ├─ 选择人饭菜单
│  ├─ 编辑与评估本餐
│  ├─ 新增/编辑狗狗档案
│  └─ 本餐记录详情
├─ 后续能力支线（不属于主线 P0.1）
│  ├─ 体重历史与趋势
│  ├─ 疫苗、驱虫和其他护理记录
│  └─ 吃饭、体重、护理统一时间轴
└─ 历史兼容页面（保留深链，不设主入口）
   ├─ 公共狗饭食谱列表与详情
   ├─ 制作周期与批量清单
   ├─ 历史批量清单详情
   └─ 旧自定义狗饭相关页面
```

## 4. 一级页面与中央动作职责

| 节点 | 回答的问题 | 必须承担 | 明确不承担 |
| --- | --- | --- | --- |
| 首页 | “今天接下来做什么？” | 当前唯一主任务、可恢复草稿提示、今天本餐摘要、最近一顿、现有档案缺失/不适用事项、读取失败降级 | 狗狗档案管理、历史记录浏览、体重/护理假提醒、旧食谱与批量入口 |
| 记录 | “我之前记了什么？” | 当前本餐月历、选中日列表、本餐详情入口、无记录时的统一记餐入口 | 档案管理、创建第二套本餐流程、提前混入体重或护理时间轴 |
| 狗狗 | “我有哪些狗狗，档案是否可用？” | 登录/空状态、狗狗列表、单狗概览、新增与编辑档案入口、完整/不完整/不适用状态 | 账号设置、自动医疗判断、主线阶段的体重趋势和护理记录 |
| 我的 | “我的账号和应用设置在哪里？” | 登录与账号状态、隐私、帮助、反馈和真实可用的设置入口 | 狗狗列表、档案编辑、占位菜单、旧批量能力主入口 |
| 中央“记一顿” | “现在开始或继续这一顿” | 统一复用登录、建档、选狗、资格校验、草稿恢复和选菜单规则 | 选中态、独立首页、复制业务判断、清除草稿、承载档案或记录管理 |

首页的卡片顺序、事项排序和视觉层级由 `D1.1`、`F1.3` 冻结；本文件只确定数据边界和职责，避免在 P0.1 提前固化展示算法。

## 5. 入口矩阵

| 发起位置 | 用户意图 | 目标节点 | 入口合同 |
| --- | --- | --- | --- |
| 底部“首页” | 查看今天状态 | 首页 | 切换真实 Tab，并保留首页为今日概览 canonical 目的地 |
| 底部“记录” | 回看历史本餐 | 记录 | 切换真实 Tab，不经过首页中转 |
| 底部“狗狗” | 管理狗狗与档案 | 狗狗 | 切换真实 Tab；档案管理不再由“我的”代理 |
| 底部“我的” | 管理账号与设置 | 我的 | 切换真实 Tab，不展示狗狗档案列表 |
| 底部中央“记一顿” | 开始或继续本餐 | 统一记餐入口 | 不切换 Tab 选中态；完成守卫后进入现有任务流 |
| 首页主任务 | 开始或继续本餐 | 统一记餐入口 | 与中央动作使用同一合同，不复制登录、档案或草稿判断 |
| 记录整月/当天空态 | 记录一顿 | 统一记餐入口 | 与中央动作结果一致；取消或返回不清除草稿 |
| 首页档案事项 | 完善指定狗狗 | 狗狗档案编辑任务页 | 保存或取消后回到原首页意图，具体返回参数由后续迁移合同确定 |
| 狗狗列表 | 查看一只狗 | 单狗概览 | 单狗概览归属于“狗狗”，不是独立一级目的地 |
| 狗狗列表/单狗概览 | 新增或编辑档案 | 档案编辑任务页 | 复用现有档案服务与表单，不复制档案业务规则 |
| 记录列表 | 查看保存结果 | 本餐详情任务页 | 只读保存快照；返回记录页的月份和日期上下文 |
| 旧食谱或批量深链 | 查看历史兼容内容 | 对应兼容页面 | 继续可访问，但不补回底部导航、首页卡片或新主流程入口 |

统一记餐入口的固定判断语义如下；具体函数、页面和导航方式由 `A1.1` 决定：

```text
发起记一顿
  → 未登录：完成登录后回到原记餐意图
  → 无档案：完成建档后回到原记餐意图
  → 有档案：沿用现有适用门禁、单狗/多狗选择和草稿恢复规则
  → 取消、遮罩关闭或系统返回：不清除或静默恢复草稿
```

## 6. 关键用户状态矩阵

| 状态 | 首页 | 记录 | 狗狗 | 我的 | 中央“记一顿” |
| --- | --- | --- | --- | --- | --- |
| 游客 | 展示产品价值和登录后可执行的主任务；不请求个性化档案或记录 | 展示登录后查看记录的明确空状态，不伪造历史 | 展示登录后管理狗狗的明确状态 | 展示登录入口及游客可用的真实帮助/隐私入口 | 先登录，成功后恢复本次记餐意图 |
| 已登录、无档案 | 主任务引导先建档，不展示虚构狗狗或评估 | 正常展示真实记录结果；无记录时入口仍指向统一记餐流程 | 展示档案空状态和唯一明确的新增入口 | 展示账号与设置，不承担建档列表 | 先建档，成功后恢复本次记餐意图 |
| 已登录、单狗 | 展示该狗相关的草稿、今天摘要和档案事项；不把单狗写成永久“当前狗” | 展示真实本餐记录，可按现有规则筛选/进入详情 | 展示单狗卡片与概览、完整性/适用状态和编辑入口 | 仅展示账号与设置 | 满足现有规则时可自动继续；档案不完整则完善，不适用则说明原因；草稿仍由用户决定恢复或重开 |
| 已登录、多狗 | 汇总今天状态，涉及具体狗狗的事项必须标明对象 | 展示真实本餐记录，每条明确狗狗；主线不新增跨类型筛选 | 展示全部狗狗，不制造隐式默认狗；每只狗分别显示档案状态 | 仅展示账号与设置 | 继续使用当前明确选狗规则；不同狗的资格和草稿不能串用 |

多狗状态可以同时包含完整、不完整和不适用档案。列表与选择流程必须逐只展示真实状态；不得因为存在一只可用狗而隐藏其他狗，也不得用一只狗的资格、草稿或记录替代另一只狗。

## 7. 无冲突约束

以下约束用于判断后续设计和实现是否偏离已冻结信息架构：

- 同一能力只有一个一级归属：档案归“狗狗”，账号设置归“我的”，历史本餐归“记录”，今日下一步归“首页”。
- 三个“记一顿”发起位置只有一个行为合同；页面可以有不同文案，但不能产生不同守卫结果。
- 登录和建档是记餐意图中的可恢复守卫，不是导致用户丢失原意图的终点。
- 单狗自动继续与多狗明确选择不构成“当前狗”全局状态；记录、草稿和档案始终保留具体狗狗身份。
- 首页数据失败不阻断统一记餐入口；记录读取失败不改变首页或狗狗档案状态。
- 任务型子页面不同时承担一级导航；返回时回到发起上下文，不通过新增重复首页解决返回问题。
- 旧兼容页面继续可读不等于继续推广；兼容入口不得与新主导航形成第五、第六个隐性目的地。
- 体重、护理和统一时间轴未完成前，不使用占位卡片、假数据或医疗推导填充主线页面。

## 8. 主线与后续支线边界

P0.1 冻结的是现有能力重排：四目的地、中央动作、狗狗档案迁移、精简“我的”、自适应首页和本餐记录衔接。

以下能力必须等主线 `V1.1` 完成后按独立节点推进：

- 每次称量形成的体重历史、最新体重同步与趋势页；
- 疫苗、体内驱虫、体外驱虫和其他护理事实记录；
- 基于用户填写日期的护理事项；
- 吃饭、体重和护理的统一记录时间轴。

主线不得为这些后续能力预建虚假入口或假数据，但页面和模块设计不得阻止后续通过明确入口接入。
