## 1. 目标与边界

本合同只冻结体重领域的词汇、测量记录字段、当前体重投影和删除回退语义，为后续 W1.2 提供稳定输入。它不创建 CloudBase 集合、索引、云函数或权限资源，也不改页面、首页事项、统一时间轴、线上数据或历史本餐快照。

机器可读记录合同为 [`weight-measurement-v1.schema.json`](../../../contracts/weight/weight-measurement-v1.schema.json)，运行时纯函数实现为 [`services/weightContract.js`](../../../services/weightContract.js)。

## 2. 领域定义

### 当前体重

当前体重是单只狗狗供后续新建本餐计算使用的当前状态。它不是一条历史测量记录；历史本餐使用保存时快照，不因当前体重变化而重算。

### 体重测量记录

体重测量记录是某只狗狗在一个称量日保存的一次测量事实。记录符合 `weightMeasurement/v1` 才能参与趋势和当前值计算。记录身份、所属狗狗、称量值、称量日和创建时间均为合同字段。

### 最新有效记录

在当前自然日之前（含当天）的合同有效记录中，先按 `measuredOn` 倒序，再按 `createdAt` 倒序，最后按 `id` 倒序，取唯一第一条。这样同一天重复称量也有稳定结果；无有效记录时返回空。

## 3. `weightMeasurement/v1` 字段合同

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `schemaVersion` | `1` | 固定版本号 |
| `id` | string | 非空，服务端生成的记录身份 |
| `dogId` | string | 非空，只属于当前用户拥有的狗狗 |
| `weightKg` | number | 大于 `0`，最多两位小数，单位固定为 kg |
| `measuredOn` | `YYYY-MM-DD` | 必填，不能晚于当前自然日；按项目 Asia/Shanghai 自然日判断 |
| `createdAt` | ISO datetime | 服务端创建时间，用于同日测量稳定排序 |

合同禁止额外字段，客户端或云函数 DTO 不应把 `_id`、`_openid` 泄漏成业务字段。W1.2 负责将 CloudBase 内部 ID 映射为 `id`，并校验 `dogId` 归属。

## 4. 当前体重投影

`resolveCurrentWeight` 的来源优先级如下：

1. 有合同有效测量记录：使用最新有效记录的 `weightKg`、`measuredOn` 和 `id`，来源标记为 `measurement`。
2. 没有任何历史测量记录：兼容既有档案 `dogs.weightKg`，来源标记为 `legacy-profile`；不虚构测量日期或记录 ID。
3. 已经有历史记录但当前没有有效记录：返回 `none`，不能重新回退到旧 `weightKg`。

这意味着旧 `weightKg` 只能作为无历史时的兼容当前值，不能自动变成一条带日期的历史记录，也不能参与趋势图。W1.2 第一次保存真实测量后，应让历史记录成为当前值来源；删除最后一条测量时同步清空档案当前体重，避免旧字段再次“复活”。

## 5. 删除与回退合同

- 删除必须由上层完成二次确认；领域函数只计算删除后的结果，不负责弹窗或持久化。
- 删除最新有效记录且存在上一条有效记录：当前体重回退到上一条记录。
- 删除最新有效记录且不存在上一条有效记录：当前体重变为未记录状态。
- 删除非最新历史记录：当前体重保持不变。
- 删除计算返回新数组，不修改调用方传入的历史数组。
- 删除体重记录不影响已经保存的本餐记录，因为本餐记录使用快照。

## 6. `weightKg` 迁移策略

### 读取兼容

W1.2 初次上线读取时不批量回填线上历史：没有体重测量记录的旧档案继续把合法 `weightKg` 展示为当前体重，但只标记为 `legacy-profile`，不生成历史日期和趋势点。空值、零值、负值和非有限值视为未记录。

### 新写入边界

新增测量必须使用 `weightMeasurement/v1` 的日期和两位小数规则。成功保存后，最新测量同步为档案当前 `weightKg`；已有本餐快照不重算。

### 删除与收口

第一次保存真实测量后，体重历史成为权威来源。删除最新测量按第 5 节回退，并在没有上一条时清空档案当前 `weightKg`。本策略不自动迁移线上数据，历史初始化和任何云端写入都属于后续 W1.2/OW1 的授权范围。

## 7. 下游任务边界

- **W1.2：** 实现独立体重 service、adapter、云函数、集合 schema、索引、权限、分页、失败恢复和测试；不得把体重写模型并入护理或本餐记录。
- **W1.3：** 使用本合同实现趋势、历史、空态、表单和删除确认；编辑必须遵循既定的历史事实策略，不改变本餐快照。
- **H2.1：** 只有在 W1.3 和授权部署完成后，才能把真实体重事项接入首页；只表达“上次记录于多久前”，不生成健康结论。
- **R2.1：** 后续统一时间轴只读取体重结果，不把体重、护理和本餐合成一个万能写模型。
