# 营养评估模块设计说明

## 1. 目标

将食谱设计页中的“营养汇总”改为“营养评估”，帮助主人判断某只狗当天这一餐是否符合参考标准，并直接完成下一步调整。

模块需要同时满足两类用户：

- 普通用户在收起态即可看到总体状态和一条最重要的调整建议。
- 进阶用户在展开态可以查看国标与 FEDIAF 的独立建议、调整入口和全部营养元素对照。

本设计只定义评估界面的信息架构、文案语义和交互入口，不设计“挑选富含对应营养元素的食物”后续页面，也不修改现有 Figma 设计稿。

## 2. 评估对象与口径

评估对象是某只狗当天的一餐，不是长期固定食谱，也不是主人当天所有食物的汇总。

系统从狗狗档案读取年龄阶段、体重、活动水平、每日餐数等信息，先计算全天目标，再按每日餐数等额分配为本餐目标：

```text
狗狗档案
  -> 全天营养目标
  -> 本餐目标 = 全天目标 / 每日餐数
  -> 当前食谱营养总量
  -> 国标与 FEDIAF 独立评估
```

评估界面必须显示“每日几餐中的一餐”，让用户知道当前参考值的分配依据。标准原始值如采用干物质或能量基准，应先转换为可比较的本餐参考值，并在口径说明中保留原始来源。

## 3. 信息层级

模块采用三层渐进信息结构：

1. 收起态：总体状态和一条首要建议。
2. 展开态：评估结论、国标建议、FEDIAF 建议及直接调整入口。
3. 进阶内容：全部营养元素的标准对照表。

完整顺序如下：

```text
收起态
  总体状态 + 首要建议

展开态
  评估结论
  国标评估与调整入口
  FEDIAF 评估与调整入口
  全部元素对照（默认收起）
  评估口径与免责声明
```

不设置百分制综合得分，不把两个标准合并为一个结论。两个标准的元素数量、上下限和适用条件不同，合并得分会制造不可靠的精确感。

## 4. 收起态

收起态只使用国标生成总体状态与首要建议，不展示多项营养数字，也不同时引入 FEDIAF 结论。

示例：

```text
营养评估                         查看详情 >
需要调整
优先补充含钙食材，本餐钙含量低于国标参考要求
```

整个收起区域均可点击展开，“查看详情”只作为辅助提示。建议文案最多两行，避免底部抽屉过度占用食材编辑区域。

### 4.1 总体状态

总体状态只使用以下四档：

| 状态 | 含义 |
| --- | --- |
| 基本合适 | 已评估的国标项目均处于参考范围内 |
| 建议调整 | 存在一般偏低或偏高项目 |
| 需要调整 | 存在优先级较高或偏差较大的项目 |
| 暂无法评估 | 食材营养、水分或狗狗档案数据不足 |

不使用“营养均衡”“完全达标”“风险”等绝对或诊断式表述。

### 4.2 首要建议

首要建议遵循确定性优先级：

1. 超过安全上限的元素。
2. 偏差最大的高优先级元素。
3. 普通偏低或偏高元素。
4. 无法可靠比较时，说明最主要的数据缺失原因。

建议文案由“调整方向 + 营养元素 + 判断依据”组成，例如：

- 优先补充含钙食材，本餐钙含量低于国标参考要求。
- 适当减少高脂食材，本餐粗脂肪高于国标参考范围。
- 当前主要营养指标处于国标参考范围内。
- 部分食材缺少营养数据，当前结果可能不完整。

营养元素优先级应由评估规则或标准数据配置提供，不在 UI 中硬编码。

## 5. 展开态评估结论

展开后不重复设置含义相近的“需要调整”和“调整建议”两个栏目，而是合并为一个“评估结论”区域：

```text
评估结论

需要调整
优先补充含钙食材，本餐钙含量低于国标参考要求

3 项建议调整 · 18 项处于参考范围 · 2 项无法评估
```

评估结论只承担三项职责：

- 给出总体状态。
- 延续收起态的首要建议。
- 提供项目数量概览。

## 6. 标准档案选择

国标和 FEDIAF 各自包含多套适用档案。系统应根据狗狗档案自动推荐，同时允许用户独立切换。

```text
国标评估
参考档案：成年犬粮                    更改 >
根据豆豆的年龄阶段自动选择

FEDIAF 评估
参考档案：成年犬 · MER 95             更改 >
根据豆豆的年龄阶段与活动水平自动选择
```

### 6.1 选择规则

- 首次评估时，系统根据狗狗档案分别选择国标和 FEDIAF 推荐档案。
- 手动切换只影响当前食谱，不修改狗狗档案，也不影响其他日期的新食谱。
- 手动切换后显示“已手动选择”，并提供“恢复系统推荐”。
- 切换国标档案后，重新计算收起态、国标建议和元素表格。
- 切换 FEDIAF 档案后，重新计算 FEDIAF 建议和元素表格；收起态仍以国标为准。
- 档案信息不足时显示“需要选择参考档案”，不得静默使用默认档案。
- 界面使用普通中文名称；MER 等术语放在补充说明中，不显示内部 profile code。

国标包含两个 profile：

- `成年犬粮`。
- `幼犬粮、妊娠期犬粮、哺乳期犬粮`，三个阶段共用同一个 profile。

选择器中第二个 profile 使用短名称“幼犬及繁殖期犬粮”，并以说明文字完整列出“适用于幼犬、妊娠期犬和哺乳期犬”。标准详情和数据交接仍保留完整名称。

## 7. 国标与 FEDIAF 详细建议

两个标准独立展示完整结论，结构保持一致：

```text
国标评估
GB/T 31216-2014 · 需要调整

需要补充
钙
当前 0.42 g · 参考要求 >= 0.80 g
[挑选富含钙的食物]                    >

需要控制
粗脂肪
当前 18.2 g · 参考要求 <= 14.0 g
主要来源：五花肉 53% · 鸡蛋 23% · 食用油 18%
[查看并调整相关食材]                  >

处于参考范围
蛋白质、磷、钙磷比等 18 项
```

FEDIAF 区域按当前选择的 FEDIAF 档案独立计算并使用相同结构。相同营养元素可以在两个标准中重复出现，因为目标值和缺口可能不同，入口必须携带对应标准的上下文。

### 7.1 偏低项入口

每个偏低项都在标准建议区域直接提供“挑选富含某元素的食物”入口，不能把主要操作隐藏到进阶表格中。

入口需要携带：

- 当前食谱标识。
- 狗狗档案标识。
- 营养元素标识与显示名称。
- 当前含量与目标缺口。
- 判断来源标准及标准档案。
- 本餐目标值和计算口径。

本轮不设计入口后的食物挑选页面。

### 7.2 偏高项来源

每个偏高项直接展示贡献最高的 2 至 3 种食材，以及它们占该营养元素本餐总量的比例。其余食材合并为“其他食材”。

使用“主要来源”，不使用“导致超标”，因为超出参考范围来自食材组合，而不是单一食材的绝对因果。

“查看并调整相关食材”入口返回食谱编辑区域，并定位相关食材。贡献比例只能基于有可靠营养数据的食材计算；数据覆盖不足时必须同时提示结果可能不完整。

## 8. 全部元素对照

全部元素对照属于进阶查证内容，默认收起，不承担主要调整入口。

```text
全部元素对照                         展开 >
查看所有营养元素的含量、标准要求和满足情况
```

展开后使用横向滚动表格并固定首列：

| 营养元素 | 本餐含量 | 国标要求 | FEDIAF 要求 |
| --- | --- | --- | --- |
| 粗蛋白 | 32.0 g | >=24.0 g，满足 | >=28.0 g，满足 |
| 粗脂肪 | 18.2 g | <=14.0 g，偏高 | >=6.4 g，满足 |
| 钙 | 0.42 g | >=0.80 g，偏低 | >=0.90 g，偏低 |
| 维生素 D | 数据不足 | 未规定 | 无法评估 |

### 8.1 表格规则

- 表格展示两个标准全部元素的并集。
- 按宏量营养、矿物质、维生素、脂肪酸等类别分组。
- 提供“全部、需调整、范围内、无法评估”筛选。
- 状态使用“满足、偏低、偏高、无法评估”文字，颜色只作辅助。
- 同一元素可分别显示两个标准的不同状态。
- 从上方建议跳转到表格时，可自动筛选并定位对应元素。
- 点击元素行可查看原始标准值、换算口径和数据覆盖情况，但不重复主要操作入口。

空值必须区分：

| 文案 | 含义 |
| --- | --- |
| 未规定 | 当前标准没有该元素要求 |
| 数据不足 | 标准有要求，但当前食谱无法可靠计算 |
| 不适用 | 该要求不适用于当前犬只阶段或标准档案 |

## 9. 数据不足与边界状态

- 没有食材：显示“添加食材后开始营养评估”。
- 狗狗档案缺失：说明缺失字段，并提供返回档案完善信息的入口。
- 标准档案无法自动选择：要求用户先选择参考档案。
- 部分食材缺少普通营养元素记录：按该食材不含对应元素处理，以 0 含量参与评估。
- 营养记录存在但数值或单位无法使用，或组合、比值、干湿粮条件项等要求无法可靠计算：相关元素标记为“无法评估”，不按 0 处理。
- 水分数据不足且标准依赖干物质：不进行伪精确换算，说明缺少水分数据。
- 两个标准结论不一致：分别显示，例如“钙已满足国标参考要求，但低于 FEDIAF 参考水平”。
- 标准未规定某元素：显示“未规定”，不等同于满足。
- 网络或标准数据加载失败：保留食谱编辑内容，评估区域显示可重试状态，不阻断食谱保存。

## 10. 文案与责任边界

模块使用“参考要求、参考范围、建议调整”等克制表述，不提供医学诊断、治疗建议或效果保证。

展开内容底部固定说明：

> 营养评估用于配方参考，结果依据食材数据、狗狗档案和所选标准计算。如有健康问题或特殊营养需求，请咨询兽医或宠物营养专业人士。

同时显示当前使用的标准名称、版本、标准档案、餐数分配方式和数据覆盖情况，保证结论可追溯。

### 10.1 展开态视觉表达

展开态采用“白底报告式 + 状态细线”，避免使用大面积黄色、红色或绿色状态背景：

- 评估结论使用白底、中性细边框，状态色只用于总体状态文字。
- 偏低和偏高条目保持白底，分别以琥珀色或警示色左侧细线和状态文字表达。
- 操作入口使用白底细边框，保留主色文字和箭头，不使用整块高饱和按钮背景。
- “处于参考范围”使用勾选符号和绿色文字，不使用绿色横向色块。
- 国标与 FEDIAF 仍通过标题、分隔线和留白区分，不为每个标准增加大面积背景。
- 颜色始终只作为辅助信号，状态名称、当前值、参考要求和操作文案必须同时可见。

## 11. 验收标准

- 模块名称统一为“营养评估”。
- 收起态只显示国标总体状态和一条首要建议。
- 总体状态仅使用“基本合适、建议调整、需要调整、暂无法评估”。
- 展开态先显示合并后的评估结论，再分别显示国标和 FEDIAF 建议。
- 国标与 FEDIAF 均支持自动推荐标准档案和当前食谱内的手动切换。
- 每个偏低项在标准建议区域直接提供食物挑选入口。
- 每个偏高项直接展示主要贡献食材及贡献比例，并提供调整入口。
- 全部元素表格默认收起，展示两个标准元素并集及各自状态。
- 缺失数据、标准未规定和不适用三种状态有明确区分。
- 任何状态不依赖颜色作为唯一表达方式。
- 评估结果不使用百分制综合得分或医学诊断式文案。

## 12. 非目标

- 不设计“挑选富含对应营养元素的食物”后续页面。
- 不覆盖已评审的原 F06/F09/F10；营养评估改版在独立 Figma 页面维护。
- 不在本设计中确定营养计算算法、元素优先级数据或云函数实现。
- 不扩展当前已结构化标准的数据范围。
- 不改变狗狗档案的数据结构。
