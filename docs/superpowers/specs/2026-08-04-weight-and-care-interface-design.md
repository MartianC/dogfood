## 1. 交接结论

本轮冻结单狗概览中的体重与护理入口，以及体重历史、体重趋势、护理列表、添加、编辑和删除确认状态。画板只描述用户看到什么、如何操作和保存/删除后的可见后果，不改小程序代码、数据合同、云函数或线上资源。

设计基准为 `375 × 812 pt`，任务型子页面不显示底部 TabBar；返回使用现有小程序 NavBar。页面继续使用项目浅绿色背景、白色表面、深绿色主操作和暖色风险语义。

## 2. 设计边界

### 本轮包含

- 单狗概览中的当前体重入口和护理记录入口；
- 体重历史列表和趋势展示；
- 体重新增、编辑和删除确认；
- 护理类型筛选、护理事实列表；
- 护理新增、编辑和删除确认；
- 空态、长备注、失败/取消后的交互原则和删除后果文案。

### 本轮不包含

- 体重与护理的云端 schema、集合、索引或权限实现；
- 首页体重/护理事项接入；
- 吃饭、体重、护理统一时间轴；
- 自动推导护理周期、剂量建议、健康异常判断或医疗建议；
- 线上部署、历史数据迁移或 Git 提交。

## 4. 页面与交互合同

### 4.1 单狗概览

| 状态 | 展示 | 入口行为 |
| --- | --- | --- |
| 有记录 | 狗狗身份、当前体重、最新测量日期、护理摘要 | “查看趋势”进入体重趋势；“查看全部”进入护理列表 |
| 尚无记录 | 体重空态、护理空态和第一步动作 | “记录第一次体重”或“添加护理记录”进入对应表单 |
| 多狗 | 当前狗狗卡明确显示狗名和当前体重/记录数 | 进入体重或护理页后允许切换狗狗，不能混合不同狗的记录 |

单狗概览只显示记录摘要，不把空数据变成提醒，也不把“档案已建立”解释为健康结论。

### 4.2 体重

#### 正常态与趋势

- 体重趋势页顶部显示当前狗狗和档案中的当前体重；
- 趋势图只绘制有效测量记录，强调最近一次测量；
- 历史记录按测量时间倒序，保留每次测量事实；
- 每条历史记录提供编辑入口；删除入口在编辑态中提供，避免列表行误触删除；
- 空态只提供“记录第一次体重”，不显示趋势占位线或估算值。

#### 新增与编辑

- 体重必填，单位固定为 `kg`；
- 体重必须大于 `0`，最多保留两位小数；
- 称量日期必填，不能晚于当前自然日；
- 保存成功后，最新有效测量同步为狗狗档案的当前体重；
- 已保存的本餐记录使用快照，不因当前体重变化而重算或改写。

#### 删除

- 删除必须二次确认；
- 删除最新有效测量时，档案当前体重回退到上一条有效测量；
- 删除后没有上一条有效测量时，当前体重回到未记录状态；
- 删除历史测量不改变已经保存的本餐记录。

### 4.3 护理

#### 列表与筛选

- 固定四类事实：疫苗、体内驱虫、体外驱虫、其他护理；
- 列表默认显示“全部”，支持按类型筛选；
- 每条记录显示类型、名称（如果填写）、发生日期和下次日期（如果填写）；
- 未填写下次日期时显示“未填写下次”，不显示系统推荐日期；
- 多狗切换后只读取当前狗狗的护理事实。

#### 新增与编辑字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 类型 | 是 | 疫苗、体内驱虫、体外驱虫、其他护理 |
| 名称 | 否 | 用户自己填写的名称 |
| 发生日期 | 是 | 这次护理事实发生的日期 |
| 下次日期 | 否 | 用户自己确定的计划日期 |
| 备注 | 否 | 医院、品牌或其他事实说明，允许自然换行 |

护理表单不出现“推荐周期”“建议日期”“剂量”或健康结论。

#### 删除

- 删除必须二次确认；
- 删除后无法恢复；
- 如果首页后续引用了这条记录生成事项，删除后该事项不再出现；
- 删除不影响体重或本餐记录。
