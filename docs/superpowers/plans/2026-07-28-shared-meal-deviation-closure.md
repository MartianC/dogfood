## 1. 已确认的裁决

### 1.1 保持现状，不再列为偏差

- 不自动生成任何食材的首次克重或比例。
- 系统只计算本餐能量目标；用户填写全部首次克重后，可主动确认等比例调整整餐。
- 不建设 `initialMealAllocationService`，不实现营养优化配比，也不补写相关算法测试。
- 人饭数据发布门禁已经解除，本计划不再包含活动投影切换、数量扩容或 staging 激活任务。
- 现有结构化狗狗适用范围门禁继续保留。

### 1.2 本轮明确不做

- 不做照片选择、上传、云存储、保存或详情展示。
- 不重新设计当前已经满足需求的首页、选狗页、狗饭克重编辑区、本餐评估组件和三 Tab 基础结构；compose 备注与责任提醒按 2026-07-30 用户反馈暂时不展示。
- 不删除旧食谱、旧批量清单页面和历史数据。
- 不引入新的 UI 组件库、测试框架、构建工具或自动生成算法。
- 不在一个任务中同时修改数据合同、业务服务、多个页面和云环境。

### 1.3 仍需收敛的偏差

产品与交互偏差：

- 人饭菜单只支持单菜，缺少多菜选择、独立展开/选择、已选摘要、分页和返回恢复。
- 狗饭创建页的“今天的人饭”不能移除或重新加入来源食材，blocked 原因和生活化称量口径表达不完整。
- 已有草稿会静默恢复，缺少“继续编辑 / 重新开始”的明确选择。
- 本餐记录云端链路、列表分页、日期分组和完整快照详情仍未形成可验收闭环。

工程偏差：

- 页面、服务和云函数仍散落直接比较 `blocked` 的实现。
- 高保真设计确认和导航迁移门禁没有形成可持续执行的机器证据。
- 基础功能、产品设计、架构文档和个别页面文案仍混有旧批量制作口径。

## 2. 执行粒度与通用门禁

### 2.1 小任务边界

每个任务必须满足：

- 只解决一个可独立验收的问题。
- 原则上只修改一个领域模块或一个页面；生产代码尽量不超过 6 个文件，测试、工作日志和纯契约文件不计入。
- 不把 Figma 设计和小程序实现放在同一次修改中。
- 不把云函数部署、集合/索引变更和客户端代码修改放在同一次修改中。
- 不顺手重构相邻但与验收条件无关的页面或组件。
- 每个任务完成后立即追加 `docs/work-logs/2026-07-28.md` 或当日工作日志。
- 每个任务独立运行与范围匹配的测试；测试失败时先记录原因，再修实现或测试。
- 每次 Git 提交继续单独取得用户明确允许，不自动提交、推送、部署或切换云环境状态。

### 2.2 UI 任务门禁

凡任务会修改 WXML、WXSS、可见文案、交互位置、页面状态或固定底部区域，必须先完成对应 Figma 任务并取得用户确认。

Figma 交付至少包含：

- 文件、页面和 frame/node 链接，基准宽度和目标 viewport。
- 默认、加载、错误、空态、禁用、长文案和长列表中的相关状态。
- 固定底部、安全区、键盘遮挡、滚动容器和点击目标规格。
- Figma variable 到现有设计 token 的映射。
- Figma component 到 `components/ui/*`、`components/vendor/*` 或现有业务组件的映射。
- 明确列出“沿用现状、不重做”的页面区域。
- 在 `docs/ui/figma-implementation-notes.md` 记录来源、实现边界和已知差异。

没有用户确认的 Figma frame，不开始对应 WXML/WXSS 修改。仅有测试、编译或开发者自审不能替代该确认。

### 2.3 UI 冻结范围

除非后续发现阻断性缺陷，以下区域在本计划中保持现状：

- 首页问候、主操作和最近一顿区域。
- 选狗列表、单狗自动继续、档案 incomplete/blocked 提示。
- compose 顶部本餐能量目标卡。
- compose 的狗饭食材克重输入、删除按钮和额外添加入口的基础布局。
- 现有 `nutrition-assessment` 组件及其等比例调整交互。
- compose 的历史备注字段和记录数据结构继续保留，但创建页暂时不展示备注输入和责任提醒。
- 自定义 TabBar 的三个主入口及基础视觉。

**原因：** 云函数部署包不能依赖包外运行时文件，但仍需通过机器契约防止语义分叉。

**验证：** 四态一致性、伪造 blocked 保存拒绝、现有幂等测试通过。

## 6. 完成定义

本计划只有在以下条件全部满足时才完成：

- 当前文档明确以 PRD 为准，不再把自动克重或营养优化比例列为待实现能力。
- 客户端、草稿服务和记录云函数均通过具名规则函数判断食材资格，静态门禁阻止散落比较。
- 用户能选择多道人饭，展开与选择互不冲突，并在返回后恢复菜单搜索会话。
- compose 来源区支持加入、移除和重新加入，blocked 与未映射状态不可绕过。
- 用户进入已有草稿时必须明确选择继续或重新开始。
- 记录 save/list/get 云端链路、集合和索引经过授权部署并通过幂等烟测。
- 记录列表支持稳定分页与日期分组；详情展示完整单餐快照、双轴评估和版本，不包含照片功能。
- 所有涉及 UI 的改动均有先行 Figma frame、用户确认、token/component 映射和同 viewport 视觉验收。
- 当前满足需求的首页、选狗、克重编辑、评估和 TabBar 没有被无关重做；compose 备注与提醒仅按用户明确反馈暂时移除。
- 基础功能、产品设计、架构、领域和用户可见文案只表达当前共享本餐主线，旧批量功能明确标为兼容保留。
- 自动化、开发者工具核心路径和视觉验收全部通过。
