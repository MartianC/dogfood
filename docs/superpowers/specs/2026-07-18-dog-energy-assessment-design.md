# 犬只本餐能量与营养密度评估设计说明

## 1. 背景

现有营养评估将当前食谱换算为每 100 g 干物质中的营养素浓度，再与国标及 FEDIAF 档案比较。该计算可以回答“食材组成是否符合参考标准”，但食谱整体等比例放大或缩小后，营养密度不会改变，因此无法回答“这一餐的份量是否接近这只狗的能量需求”。

本设计在保留现有营养密度评估的基础上，新增独立的能量需求和能量供给评估，使用户能够同时判断：

1. 本餐份量提供的能量是否接近估算目标。
2. 本餐食材组成的营养密度是否符合参考标准。

### 1.1 与既有设计的关系

本设计是对《营养评估模块设计说明》的增量修订，并覆盖其中以下旧约束：

- 狗狗阶段不再由 `ageStage` 输入，改为根据出生日期推导。
- “本餐目标”不再只是界面口径，新增可执行的能量需求与供给计算。
- 原“不改变狗狗档案数据结构”的非目标不再适用。

既有国标与 FEDIAF 营养密度比较、标准独立展示、偏低食物入口、偏高来源说明和全部元素对照继续有效。

## 2. 设计原则

- 能量评估与营养密度评估保持独立，不用一个总体状态掩盖两类问题。
- 年龄阶段只由出生日期和当前日期推导，不允许用户同时填写出生日期与年龄阶段。
- 品种由用户从受控列表选择；预计成年体重由版本化品种数据源估算并只读展示，不要求也不允许用户手工填写。
- 活动输入只采集日均活动时长，不要求用户判断活动强度；活动水平由固定时长阈值在内部推导。
- 使用 FEDIAF 2025 的生命周期与活动模型计算能量起始值，与项目现有 FEDIAF 营养标准保持一致。
- 公式结果使用“估算目标、起始参考”等表述，不使用“肯定吃不饱、一定喂多了”等绝对判断。
- 数据不足只阻断依赖该数据的结论；能量和营养密度允许分别成功或失败。
- 计算逻辑使用无界面依赖的纯函数实现，便于边界测试和后续校准。

## 3. 领域术语与评估对象

### 3.1 术语

| 术语 | 定义 |
| --- | --- |
| 每日能量估算目标 | 根据犬只档案和 FEDIAF 模型得到的每日代谢能起始参考值 |
| 本餐能量目标 | 每日能量估算目标按每日餐数等额分配后的结果 |
| 本餐能量供给 | 当前食谱中所有有效食材按克重汇总的估算能量 |
| 营养密度 | 单位干物质或单位能量中的蛋白质、矿物质、维生素等营养素浓度 |
| 营养标准阶段 | 用于选择幼犬早期、幼犬晚期或成年犬营养标准的内部阶段 |
| 能量计算阶段 | 用于选择幼犬生长公式、成年犬活动模型或老年犬起始口径的内部阶段 |

### 3.2 评估对象与假设

评估对象仍是某只狗当天的一餐。系统默认每日各餐等量：

```text
本餐能量目标 = 每日能量估算目标 / 每日餐数
```

零食、营养膏、其他额外食物以及不同配方的其他餐次不计入当前结果。界面必须展示这一口径，避免用户将本餐结果误解为全天完整摄入评估。

## 4. 狗狗档案

### 4.1 字段

| 字段 | 要求 | 用途 |
| --- | --- | --- |
| `birthDate` | 所有犬只必填 | 推导实际年龄、营养标准阶段和能量计算阶段 |
| `breed` | 必填选择；允许“混血/不确定” | 查询品种数据源并估算成年体重 |
| `weightKg` | 必填且大于 0 | 计算代谢体重和能量需求 |
| `dailyMeals` | 必填且大于 0 | 将每日目标分配为本餐目标 |
| `dailyActivityHours` | 必填，0–6 小时，步进 0.5 小时 | 由日均活动时长派生四档活动水平 |
| `activityLevel` | 内部派生/兼容字段 | 选择成年犬和老年犬活动系数；新表单不直接编辑 |
| `bodyCondition` | 必填 | 展示个体校正提示，不直接生成减重或增重处方 |
| `expectedAdultWeightKg` | 系统估算、只读；可能不可用 | 根据品种数据源估算，供幼犬生长能量需求使用 |
| `neutered` | 选填 | 保留个体资料，本版不直接修改 FEDIAF 系数 |
| `allergens` | 内部保留，界面暂时隐藏 | 兼容既有档案；保存其他档案字段时不得清空 |
| `avoidIngredients` | 内部保留，界面暂时隐藏 | 兼容既有档案；保存其他档案字段时不得清空 |
| `ageStage` | 停止新增和编辑 | 仅兼容旧数据，不再作为计算依据 |

品种数据源必须有明确版本，且只提供成年体重估算，不作为品种专属能量系数。选择“混血/不确定”或数据源没有可靠估算时，档案仍可保存，`expectedAdultWeightKg` 返回不可用；成年犬和老年犬能量不受影响，幼犬只继续营养密度评估并将能量结论降级为不可用。任何降级状态都不得改为让用户手工填写预计成年体重。

### 4.2 日均活动时长与活动水平

档案页使用横向 Slider 收集 `dailyActivityHours`，范围为 0–6 小时，步进 0.5 小时。Slider 背景按四段使用不同颜色，拖动时实时显示“日均 X 小时 · 水平名称”。用户只选择时长，不选择活动强度。

| `dailyActivityHours` | 派生 `activityLevel` | 用户文案 |
| --- | --- | --- |
| 0 至不足 1 小时 | `low` | 低活动 |
| 1 至不足 2 小时 | `moderateLowImpact` | 一般活动 |
| 2 至不足 3 小时 | `moderateHighImpact` | 较多活动 |
| 3 至 6 小时 | `high` | 高活动 |

这四档是产品基于活动时长对 FEDIAF 活动系数的映射，用于在不要求用户判断强度的前提下提供一致起始值；其中 1–不足 2 小时和 2–不足 3 小时的拆分是产品规则，不是 FEDIAF 对“1–3 小时低/高强度”分类的逐字复刻。

新档案保存 `dailyActivityHours`，并同步派生 `activityLevel`。旧值 `normal` 兼容映射为 `moderateLowImpact`；旧值 `high` 保持为 `high`。旧档案只有 `activityLevel` 而没有时长时，可临时沿用该兼容值计算，并提示用户通过 Slider 完善时长；两者同时存在时始终以 `dailyActivityHours` 重新派生，不能信任冲突的旧值。

### 4.3 体况

首版使用生活化的三档选择：

- `thin`：偏瘦。
- `ideal`：理想。
- `overweight`：偏胖。

体况用于提醒公式结果需要结合体重变化校正。首版不根据体况直接改变能量系数，因为安全的减重或增重目标还需要目标体重、健康状况和专业判断。

## 5. 内部生命周期估算

系统使用本地自然日计算周龄和年龄，避免时区造成边界日期相差一天。用户只填写出生日期，页面展示“系统估算”结果，不提供年龄阶段选择器。

| 实际年龄 | 营养标准阶段 | 能量计算阶段 |
| --- | --- | --- |
| 小于 8 周 | 不自动评估 | 不自动评估 |
| 8 周至不足 14 周 | 幼犬早期生长 | 幼犬生长 |
| 14 周至不足 1 岁 | 幼犬晚期生长 | 幼犬生长 |
| 1 岁至不足 7 岁 | 成年犬 | 成年犬 |
| 7 岁及以上 | 成年犬 | 老年犬 |

老年犬没有独立的 FEDIAF 营养密度档案，因此继续使用成年犬营养标准，只在能量起始口径和说明中体现老年阶段。7 岁是通用估算分界，实际阶段受品种、体型、活动和健康状况影响；界面不得将其描述为医学认定。

### 5.1 边界校验

- 出生日期晚于当前日期时禁止保存。
- 小于 8 周时不自动给出份量或配方结论，并提示咨询兽医。
- 品种必填，但“混血/不确定”以及暂无可靠估算的品种允许保存。
- 幼犬无法从品种数据源取得可靠的预计成年体重时，允许继续完成可用的营养密度评估，但能量结论不可用；界面不得出现手工填写成年体重的替代入口。
- 幼犬的品种估算值与当前体重明显不一致时，同样将能量结论降级为不可用并标记数据需要复核，不把问题转成用户手填成年体重的字段错误。
- `dailyActivityHours` 超出 0–6 小时或不是 0.5 小时步进时禁止保存；0 小时是合法输入。
- 超过 1 岁仍保留旧 `ageStage=puppy` 不影响结果，系统始终以出生日期推导值为准。
- 日期跨越 14 周、1 岁或 7 岁边界后，下次评估自动使用新阶段。

## 6. 每日能量需求

### 6.1 幼犬

8 周至不足 1 岁使用 FEDIAF 生长公式：

```text
每日能量估算目标（kcal）
= [254.1 - 135 ×（当前体重 kg / 预计成年体重 kg）]
  × 当前体重 kg^0.75
```

该公式的结果是生长阶段的平均起始值，不替代定期称重、生长曲线和兽医建议。

### 6.2 成年犬和老年犬

`dailyActivityHours` 完整时，成年犬和老年犬均使用其派生活动水平匹配 FEDIAF 活动模型：

```text
每日能量估算目标（kcal）= 活动系数 × 当前体重 kg^0.75
```

| 由时长派生的活动水平 | 日均活动时长 | kcal ME / kg BW^0.75 |
| --- | --- | ---: |
| 低活动 | 0 至不足 1 小时 | 95 |
| 一般活动 | 1 至不足 2 小时 | 110 |
| 较多活动 | 2 至不足 3 小时 | 125 |
| 高活动 | 3 至 6 小时 | 150–175 |

旧档案没有 `dailyActivityHours` 但保留有效兼容 `activityLevel` 时，临时沿用兼容值；两者都缺少时：

- 成年犬临时使用 110。
- 老年犬临时使用 95。
- 结果标记为“使用兼容/默认活动水平估算”，并提供通过 Slider 完善时长的入口。

由实际时长派生的活动水平优先于兼容值和年龄默认值。活跃的老年犬不能仅因年龄被强制降低到 95；同样，活动较少的成年犬不应默认使用高活动系数。

## 7. 本餐能量供给

### 7.1 汇总公式

```text
单项食材能量 = 食材克重 × 每 100 g 能量 / 100
本餐能量供给 = 所有有效食材能量之和
```

### 7.2 数据来源优先级

1. 使用营养数据库中有效的每 100 g 能量记录。
2. 能量记录缺失，但计算所需的蛋白质、脂肪和碳水数据完整时，按统一的 FEDIAF 适用公式估算，并标记为“宏量营养估算”。
3. 两种方式均不可用时，将该食材标记为“能量数据不足”。

只要存在无法估算能量且克重大于 0 的食材，就不输出确定的偏少或偏多状态。界面可以展示已知食材提供的能量下限和缺失食材，但不得将下限作为整餐总能量。

## 8. 能量状态

固定目标值使用可配置的展示容差：

| 当前能量 / 本餐目标 | 状态 | 文案 |
| --- | --- | --- |
| 少于 90% | `below_target` | 能量低于估算目标 |
| 90%–110% | `near_target` | 能量接近估算目标 |
| 高于 110% | `above_target` | 能量高于估算目标 |
| 档案或食材数据不完整 | `unavailable` | 暂无法判断本餐份量 |

90%–110% 是用于降低克重输入误差和界面频繁跳变的产品展示容差，不是医学上的安全上下限。高活动犬得到原生目标范围时，直接以目标范围比较，不再叠加 10% 容差。

## 9. 与营养密度评估的组合

### 9.1 双轴结论

模块名称使用“本餐评估”，收起态同时显示两个独立结论：

```text
本餐评估                         查看详情 >

能量接近估算目标
当前约 286 kcal · 估算目标 310 kcal

营养密度需要调整
钙低于幼犬晚期生长参考要求
```

不再使用一个总体状态表示全部结果。允许出现以下组合：

| 能量 | 营养密度 | 解释重点 |
| --- | --- | --- |
| 接近目标 | 合适 | 份量和主要营养密度均接近参考 |
| 偏少 | 合适 | 保留食材比例，整体增加克重 |
| 偏多 | 合适 | 保留食材比例，整体减少克重 |
| 接近目标 | 需调整 | 份量基本合适，调整食材组成 |
| 偏少或偏多 | 需调整 | 先调整组成，再依据重算结果调整总量 |
| 不可用 | 可评估 | 继续展示营养密度，明确不能判断份量 |
| 可评估 | 不可用 | 继续展示能量，明确不能判断营养密度 |

### 9.2 展开态结构

```text
本餐评估
  份量与能量
  营养密度
    国标评估
    FEDIAF 评估
    全部营养元素
  计算依据与说明
```

“份量与能量”展示：

- 本餐实际能量。
- 本餐估算目标或目标范围。
- 当前能量占目标的比例。
- 每日估算目标和每日餐数。
- 系统估算生命周期、活动水平和是否使用默认值。
- 能量数据覆盖情况。
- 不包含零食及额外喂食的口径说明。

## 10. 调整动作

### 10.1 按目标调整整餐份量

能量偏少或偏多时提供“按目标调整整餐份量”：

```text
当前：240 g / 286 kcal
建议：约 260 g / 310 kcal
```

系统按相同比例缩放所有食材克重，并在确认弹层中预览调整前后的总克重、能量和各食材克重。用户确认后才写回食谱。等比例缩放不改变营养密度，因此营养密度状态保持不变。

高活动犬存在目标范围时，界面展示建议总克重范围，并以范围下界作为保守起始预览；用户仍需确认。

### 10.2 调整食材组成

营养密度偏低或偏高时继续使用现有入口：

- 偏低：挑选富含对应营养素的食物。
- 偏高：查看并调整主要来源食材。

任何食材新增、删除或克重变化都会使先前份量建议失效。页面必须实时重新计算能量和营养密度，再生成新的调整建议。

## 11. 模块设计

### 11.1 `lifeStageEstimator`

职责：根据出生日期和计算日期输出周龄、年龄、营养标准阶段、能量计算阶段和边界错误。

该模块不读取档案、不访问网络，也不决定界面文案。

### 11.2 `energyRequirementService`

职责：根据生命周期估算结果、体重、品种估算的预计成年体重、日均活动时长和餐数，输出每日目标、本餐目标、目标范围、计算公式标识和是否使用兼容值。成年犬和老年犬的活动水平必须由 `dailyActivityHours` 推导；仅在旧档案缺少时长时读取兼容 `activityLevel`。

### 11.3 `breedAdultWeightEstimator`

职责：根据受控品种值和版本化品种数据源返回只读的预计成年体重、数据版本与不可用原因。该模块不接受用户输入的成年体重；“混血/不确定”或无可靠数据时返回不可用，但不阻断档案保存。

### 11.4 `mealEnergyService`

职责：汇总食材能量、记录每种食材的计算来源和数据缺口，并生成等比例调整预览。该模块不负责营养密度判断。

### 11.5 `nutritionAssessmentService`

继续负责现有国标与 FEDIAF 干物质营养密度评估。自动选择档案时改用 `lifeStageEstimator` 的营养标准阶段，不再读取用户填写的 `ageStage`。

### 11.6 `mealAssessmentService`

组合能量需求、能量供给和营养密度结果，向组件提供双轴展示模型。任一子评估失败时保留另一个成功结果。

## 12. 异常与降级

- 没有食材：提示添加食材后开始本餐评估。
- 缺少出生日期：要求完善档案，不猜测生命周期。
- 新档案缺少或含无效 `dailyActivityHours`：要求用户通过 Slider 完善；旧档案只有兼容 `activityLevel` 时可临时计算，并明确降低结果可信度。
- 幼犬选择“混血/不确定”或品种数据源无可靠预计成年体重：能量不可用，营养密度继续评估，不要求用户手填成年体重。
- 过敏源与忌口控件暂时隐藏；编辑并保存其他档案字段时，原有 `allergens` 与 `avoidIngredients` 必须原样保留。
- 能量数据缺失：展示已知能量下限和缺失食材，营养密度继续评估。
- 水分数据缺失：营养密度不可用，能量评估继续显示。
- 标准数据加载失败：不阻断只依赖档案和食材能量的能量评估。
- 网络错误：保留食谱草稿、克重和最近一次输入，不阻断保存。
- 体况为偏瘦或偏胖：展示监测体重和咨询专业人士的提示，不自动生成治疗性目标。

## 13. 测试策略

### 13.1 单元测试

- 8 周、14 周、1 岁和 7 岁前后一天的生命周期边界。
- 闰年生日、本地自然日和跨时区输入。
- 幼犬公式、品种估算成年体重可用/不可用和小数体重。
- Slider 的 0、0.5、1、1.5、2、2.5、3、6 小时边界、四档派生结果、旧活动值兼容和高活动范围。
- 品种必填、“混血/不确定”可保存、品种数据源无可靠估算时幼犬能量单侧降级。
- 隐藏过敏源/忌口控件后，编辑保存不会清空既有 `allergens` 与 `avoidIngredients`。
- 能量记录优先、宏量营养回退、部分食材缺失和单位异常。
- 90%与110%的状态边界。
- 等比例缩放后能量按比例变化、营养密度保持不变。
- 能量成功但营养密度失败，以及相反组合。
- 旧活动值映射和旧 `ageStage` 不再参与计算。

### 13.2 集成与回归测试

- 完善档案后食谱编辑页自动重算。
- 食材新增、删除和克重修改使旧建议失效并重新计算。
- 调整预览取消时不修改草稿，确认时一次性写回全部食材。
- 当前国标和 FEDIAF profile 切换、偏低入口、偏高来源及全部元素表格保持正常。
- 现有营养评估、食材搜索、草稿保存和云端分页测试继续通过。

### 13.3 人工验证

- 档案始终提供品种选择；幼犬只读显示品种估算的预计成年体重或不可用状态，不出现手工输入框。
- 活动 Slider 只按时长分四档，拖动时实时显示日均时长和水平名称，不出现强度选择。
- 收起态在小屏幕上清楚展示两个结论且不遮挡食材编辑。
- 展开态明确展示计算依据、默认值和数据缺口。
- 份量调整预览不会造成克重截断、负值或比例漂移。
- 文案不使用医学诊断、效果保证或虚假的精确表达。

## 14. 实施阶段

1. 扩展狗狗档案、云端字段、表单校验和旧数据兼容。
2. 实现生命周期估算和能量纯计算服务及单元测试。
3. 将能量结果与现有营养密度结果组合为本餐评估。
4. 更新收起态和展开态，保留两条独立状态链路。
5. 实现按比例调整整餐克重和确认预览。
6. 运行自动化测试、UI 静态检查和微信开发者工具核心路径验证。

## 15. 验收标准

- 用户只填写出生日期，不选择年龄阶段。
- 用户必须选择品种；预计成年体重由版本化品种数据源估算并只读展示，不能手工填写。
- 用户只通过 0–6 小时、0.5 小时步进的横向 Slider 选择日均活动时长，四档活动水平按固定时长阈值实时派生，不要求选择活动强度。
- 系统能在 8 周、14 周、1 岁和 7 岁边界选择正确内部阶段。
- 品种存在可靠成年体重估算时，幼犬、成年犬和老年犬均可在档案完整时得到能量估算目标。
- 混血/未知品种或无可靠成年体重估算时仍可保存档案；幼犬能量不可用但营养密度继续评估。
- 档案页暂时不显示过敏源和忌口控件；编辑其他字段后既有 `allergens` 与 `avoidIngredients` 数据不丢失。
- 老年犬使用成年犬营养密度标准，不虚构独立老年犬营养档案。
- 收起态同时展示能量和营养密度结论，不合并为一个模糊状态。
- 配方密度合适但份量不足时，能够按比例预览并调整整餐克重。
- 份量合适但营养密度不合适时，继续引导调整食材组成。
- 能量或营养密度一侧数据不足时，另一侧可用结论不受阻断。
- 计算依据包含标准版本、生命周期、活动水平、餐数、数据覆盖和额外喂食排除说明。
- 所有结果使用参考性文案，并提示通过体重和体况变化校正。

## 16. 非目标

- 不在本版记录每周体重趋势或自动学习个体校准系数。
- 不计算零食、营养膏或其他餐次的全天总摄入。
- 不提供减重、增重、妊娠、哺乳、疾病或治疗性饮食处方。
- 不使用未经项目验证的品种专属能量系数；品种数据源只用于估算预计成年体重。
- 不把公式结果解释为饱腹感、医学诊断或保证性的喂食量。
