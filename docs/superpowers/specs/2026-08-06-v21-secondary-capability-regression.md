# V2.1 次要能力完整回归交接

**状态：** 本地代码与自动化回归已完成；线上 CloudBase 烟测仍遵循体重/护理资源的独立授权边界

**日期：** 2026-08-06

**上游：** [`项目结构与界面编排 DAG 路线图`](../plans/2026-08-01-project-structure-and-interface-roadmap.md)

## 1. 本轮实施

V2.1 汇合体重、护理、首页事项和统一记录时间轴，补齐两个会影响真实回看一致性的边界：

- 记录页从体重或护理任务返回时，强制按当前月份重新读取，避免删除/更新后的旧缓存继续展示。
- 统一时间轴分页的后续请求失败时，保留该狗狗此前已成功读取的记录，并将来源标为失败/整体标为部分可用，避免把已显示内容伪装成空态。

本轮没有修改体重、护理或本餐的独立写模型，没有合并集合，也没有部署云函数、创建集合/索引或写入线上数据。

## 2. 回归范围

自动化回归覆盖：

- 体重与护理的用户/狗狗归属隔离、稳定分页、日期边界、更新和删除后的当前状态；
- 首页只消费真实体重和用户填写的护理下次日期，最多展示三条事项并保持狗狗归属；
- 统一记录页的三类来源、上海自然日、来源状态、多狗分组、详情跳转、缓存刷新和分页部分成功；
- UI、主包边界、项目导航、共享本餐导航、体重/护理合同、代码质量和 Git 空白检查。
- 共享本餐记录合同和本餐历史快照回归。

统一执行入口：

```bash
npm run check:v21-regression
```

## 3. 需要开发者工具完成的外部验收

由于本轮不自动执行线上资源变更，以下烟测需要在已授权并已部署的 CloudBase 环境单独完成：

- 两个用户不能读取、编辑或删除对方的体重/护理记录；
- 体重和护理分页跨页读取、更新、删除后，档案当前体重、首页事项和统一记录页均刷新一致；
- UTC 16:00 前后验证上海自然日边界；
- 记录页验证吃饭、体重、护理三类记录的标记、列表、详情跳转、部分失败和全量失败；
- 320pt、375pt/390pt、长狗名、长护理名称/备注、底部安全区和返回刷新状态。

线上烟测结果应记录在部署方的发布记录中，不在本轮本地工作区伪造通过证据。
