# 狗饭微信小程序产品设计文档

## 1. 文档定位

本文描述当前产品主线、信息架构、页面职责和交互边界。当前产品事实来源为
[`每日“和狗狗一起吃”单餐创建与记录 PRD`](./superpowers/specs/2026-07-26-shared-meal-checkin-prd.md)；实现偏差和任务状态见
[`“和狗狗一起吃”偏差收敛实施计划`](./superpowers/plans/2026-07-28-shared-meal-deviation-closure.md)。

旧公共狗饭食谱和批量制作方案只作为历史兼容能力记录在本文末尾，不再定义当前主流程。架构、模块边界和数据模型由独立架构与领域文档维护。

## 2. 产品定位

狗饭微信小程序帮助普通养狗家庭从自己已经决定的人饭菜单中挑选可共用的基础食材，为一只符合适用条件的狗狗单独建立、评估并记录这一顿狗饭。

“和狗狗一起吃”指同一餐使用部分共同基础食材，不是把已调味的人饭直接分给狗狗。狗饭必须单独称量、单独烹饪，不继承盐、油、酱汁和其他调味。

一句话定位：

> 从今天的人饭中挑出可共用食材，手动确定狗狗这顿吃多少，看清本餐评估并留下可追溯记录。

### 2.1 设计目标

- 从用户已经决定的人饭出发，不介入人的菜单决策。
- 把选狗、选菜单、调整狗饭、评估和保存连接成一条每日可重复的短路径。
- 只提供有依据的本餐能量目标，不生成伪精确的首次克重或食材比例。
- 让能量和营养密度缺口持续可见，并允许用户根据评估继续调整。
- 对食材安全、档案适用范围和历史快照采取一致、可追溯的边界。
- 明确区分“保存记录”和“营养认可”，不承诺单餐或长期饮食完整均衡。

## 3. 用户与适用范围

### 3.1 游客

游客可以进入首页了解当前能力，但开始建立本餐前需要微信登录。游客不能保存草稿、建立本餐记录或管理狗狗档案。

### 3.2 已登录但没有档案的用户

用户可以进入首页和“我的”，开始本餐时需要先完成建档。建档完成后返回原本的本餐流程，不要求重新从首页开始。

### 3.3 已建档用户

已建档用户可以：

- 管理多只狗狗档案。
- 每次为一只狗狗建立本餐。
- 从一道或多道人饭菜谱中选择可共用来源食材。
- 填写和调整狗饭克重，查看双轴本餐评估。
- 恢复未完成草稿，保存并回看本餐记录。

### 3.4 狗狗适用门禁

| 档案状态 | 处理方式 |
| --- | --- |
| 档案完整、满 8 周且无特殊营养需求 | 可以进入本餐创建 |
| 缺少计算必需字段或特殊状态未确认 | 保留上下文，引导完善档案 |
| 小于 8 周 | 不生成本餐，说明适用范围 |
| 疾病、妊娠、哺乳或治疗性体重管理 | 不生成本餐，提示咨询专业人士 |

系统不得用默认犬只、旧字段或伪造数值绕过上述门禁。

## 4. 信息架构

当前底部导航只有三个入口：

1. 首页
2. 记录
3. 我的

```text
首页
  → 选择本次狗狗
  → 选择人饭菜单
  → 建立这顿狗饭
  → 保存
  → 本餐详情

记录
  → 月历与选中日记录
  → 本餐详情

我的
  → 登录状态
  → 狗狗档案列表
  → 新增或编辑档案
```

旧“食谱”“清单”不再是底部 Tab。兼容页面可以由旧深链读取，但不能重新暴露为当前主入口。

## 5. 核心用户流程

### 5.1 新建本餐

1. 用户从首页点击建立本餐。
2. 系统检查登录状态；未登录时先完成微信登录。
3. 读取狗狗档案：单狗可自动选择，多狗要求用户明确单选。
4. 档案不完整时进入完善流程；不适用时停止创建并说明原因。
5. 系统检查是否存在当前草稿：有效草稿显示“继续编辑 / 重新开始”，失效草稿只允许重新开始。
6. 用户搜索自己已经决定的人饭菜单，并选择至少一道菜；可以跨搜索保留多道选择。
7. 页面按菜展示来源原料。非 `blocked` 食材可以带入，`blocked` 只读展示原因，未映射原料不制造安全结论。
8. 进入本餐创建页后，用户可以移除、重新加入来源食材，也可以通过既有入口额外添加目录食材。
9. 系统展示本餐能量目标，所有首次克重保持待填写；用户逐项填写克重。
10. 用户可以预览并确认按目标等比例调整整餐，取消预览不得修改草稿。
11. 任一食材或克重变化后，能量和营养密度双轴评估实时重算。
12. 普通营养缺口持续展示但不阻止保存；最高优先级偏高项或关键数据缺失在保存前只确认一次。
13. 保存成功只创建一条本餐记录，清除匹配草稿并进入详情；保存失败保留草稿，可安全重试。

### 5.2 恢复草稿

- 检查草稿期间不导航、不清理、不改写草稿。
- “继续编辑”进入原草稿，并使用最新狗狗档案完成必要复核。
- “重新开始”只清理匹配草稿，停留在选狗流程。
- 关闭弹层、点击遮罩或系统返回均保留草稿，不能静默恢复或静默清除。

### 5.3 查看记录

1. 进入“记录”后默认加载当前月份并选中今天。
2. 月历以“已记”表示当天至少存在一条记录，不表达连续打卡或营养结论。
3. 用户切换月份或日期，下方展示选中日的本餐列表。
4. 同日记录按用餐时间倒序展示。
5. 进入详情后只读取保存快照，不按当前档案、目录、标准或算法重算历史结果。

## 6. 页面职责

### 6.1 首页

- 承接当前主操作“和狗狗一起吃”。
- 游客状态不请求狗狗档案或记录数据。
- 登录用户可以看到最近一顿摘要；记录读取失败不能阻断主操作。
- 不展示旧公共食谱或批量清单主入口。

### 6.2 选择狗狗页

- 展示全部档案及 `eligible / incomplete / blocked` 状态。
- 单狗自动继续，多狗明确单选。
- 承接草稿检查、恢复选择和档案完善往返。
- 不在用户作出恢复决定前抢先跳转。

### 6.3 人饭菜单页

- 搜索已发布的既有人饭菜谱，支持分页、失败重试和空结果。
- 每张菜单卡的选择与展开互不影响。
- 支持选择一道或多道菜单，并在固定摘要中移除已选项。
- 返回页面时恢复关键词、已加载结果、展开项和已选菜单。
- 不提供自定义人饭菜名、原料录入或根据狗狗需求推荐人饭。

### 6.4 本餐创建页

- 展示连续的狗饭食材列表、生活化称量口径、克重输入和当前占比。
- 通过“今天的人饭”面板按菜查看来源，支持移除和重新加入非 `blocked` 食材。
- 保留额外添加食材和既有富含营养素食材入口。
- 展示能量与营养密度双轴评估，提供用户主动确认的等比例调整。
- 保存操作固定表达为记录这一餐；当前不展示照片、备注输入或长期饮食承诺。

### 6.5 记录页

- 提供月份切换、日期选择、下拉刷新和失败重试。
- 区分月份加载、月份失败、整月空态、当天空态和同日长列表。
- 当天条目只展示识别本餐所需的时间、狗狗、人饭摘要和狗饭食材数。

### 6.6 本餐详情页

- 按狗狗快照、保存时双轴评估、人饭菜单、狗饭食材、覆盖与版本、可选历史备注、责任边界的顺序展示。
- 营养不足和数据缺失必须用明确文字表达，不能只依赖颜色。
- 无备注时不保留空卡；不出现照片入口或重新计算历史结果的入口。

### 6.7 我的

- 展示登录入口和狗狗档案列表。
- 支持新增、编辑档案以及档案空状态。
- 不提供“当前狗”切换；每次本餐仍在流程内选择目标狗狗。
- 页面仍存在的旧批量文案由后续已确认的独立文案任务处理。

## 7. 关键交互与状态规则

### 7.1 食材状态

| 状态 | 搜索/展示 | 加入与保存 |
| --- | --- | --- |
| `allowed` | 正常展示 | 允许 |
| `conditional` | 展示对应说明 | 允许 |
| `unknown` | 明确数据状态 | 允许 |
| `blocked` | 展示策略原因 | 客户端和云端均禁止 |
| 未映射来源 | 只展示原文 | 不制造目录身份或安全判断 |

搜索、自动带入、来源重选、额外添加和云端保存必须使用同一非 `blocked` 规则。

### 7.2 克重与评估

- 系统只计算本餐能量目标，不填写首次克重，不决定食材或类别比例。
- 只有全部可计算食材已有有效克重时，才可预览整餐等比例调整。
- 营养标准用于评估当前输入，不用于反推食材比例。
- 普通偏低项允许保存；最高优先级偏高项或关键数据缺失需要一次确认；`blocked` 永远不能确认后继续。

### 7.3 保存与错误恢复

- 保存请求具备幂等性，重复请求不能生成重复记录。
- 保存失败时保留当前草稿和页面状态，重试不要求重新选狗或选菜单。
- 月份读取失败保留目标月份和当前选择，重试只重新读取目标月份。
- 历史记录保存不可变快照，后续版本更新不能重写保存时结论。

## 8. 内容与责任边界

产品文案保持清晰、克制、生活化：

- 使用“本餐能量目标”“本餐评估”“记录这顿”等单餐表达。
- 使用“按生重称量 / 按熟重称量 / 按干重称量 / 按当前记录口径称量”等可执行口径。
- 不使用“营养完整”“完全均衡”“自动配平”或保证长期适用的表述。
- 不把国标、FEDIAF、AAFCO 或数据库计算描述为家庭自制饮食认证。

保存前和详情页需要持续表达：

> 保存是记录本餐，不代表本餐营养完整或适合长期重复喂养。若家庭自制餐长期占主要饮食，请咨询兽医或宠物营养专业人士。

## 9. 当前范围与非目标

当前范围包括：单狗本餐、既有人饭菜单、多菜选择、来源操作、手填克重、用户确认的等比例调整、双轴评估、草稿恢复、幂等保存、月历记录和快照详情。

当前不做：

- 决定、规划或推荐用户当天的人饭。
- 自定义人饭录入或搜不到菜时按食材直接开始。
- 自动生成首次克重、食材比例、类别比例或用量上下限。
- 自动补充食材、营养补充剂或长期配方。
- 连续多餐趋势、长期完整性判断、奖励、排行或复杂统计。
- 疾病、妊娠、哺乳或治疗性体重管理方案。
- 照片选择、上传、保存或详情展示。
- 直接编辑历史记录。

## 10. 历史兼容附录：公共狗饭食谱与批量制作

### 10.1 原主线

历史版本以“浏览公共狗饭食谱 → 选择单只或多只狗狗 → 选择 7/15/30 天或自定义周期 → 按体重和每日餐数换算 → 生成采购与制作合并清单”为主线，并采用“首页、食谱、清单、我的”四个 Tab。

历史设计还包括公共食谱筛选、食谱比例与制作步骤、多狗共同制作、采购勾选、清单图片导出、分享、历史清单和自定义狗饭食谱建议。

### 10.2 当前兼容策略

- 旧食谱列表、详情、周期选择、批量清单页面和历史数据暂不删除。
- 三个旧主包深链继续保留兼容读取，但不能出现在当前底部导航。
- 旧批量数据不转换为本餐记录，也不参与当前月历和单餐评估。
- 旧页面可继续使用自身历史快照和展示合同；新的共享本餐流程不得依赖旧批量状态。
- 本附录只记录迁移边界，不表示继续扩展或重新推广旧主线。

### 10.3 不再作为当前产品承诺的旧能力

- 按制作周期自动换算每餐和采购总量。
- 多只狗狗共同制作一批饭并合并采购量。
- 从公共狗饭食谱直接生成批量清单。
- 清单导出图片、分享和采购执行状态。
- 以食谱比例或生活化阈值代替当前双轴本餐评估。

## 11. 当前验收重点

- 主导航只有首页、记录、我的，旧路由不作为主入口。
- 用户能完成选狗、多菜选择、来源操作、手填克重、双轴评估和保存记录。
- 有效草稿不会静默恢复或清除，用户必须明确选择。
- `blocked` 食材在客户端和云端均不可绕过。
- 保存重试不会产生重复记录，详情只展示保存快照。
- 页面只表达单餐结论，并持续展示数据缺口和专业责任边界。
