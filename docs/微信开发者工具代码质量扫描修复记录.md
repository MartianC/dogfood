# 微信开发者工具代码质量扫描修复记录

## 背景

微信开发者工具代码质量扫描不通过。排查时只执行本地编译和质量扫描，未上传代码、未生成预览二维码、未做真机调试。

## 扫描失败项

1. 主包存在主包未使用 JS：
   - `services/customRecipeService.js`
   - `services/fileService.js`
   - `services/planCalculatorService.js`
   - `services/recipeAdviceService.js`
   - `utils/auth.js`
2. 代码包未启用组件按需注入。
3. 图片和音频资源超过开发者工具质量扫描阈值。
4. 已提前修复并保留的项：`pages/home/index.json` 和 `pages/profile/index/index.json` 中存在未使用组件声明；根目录非运行文件需要通过 `packOptions.ignore` 排除。

## 根因

1. 根 `services/` 中有多份服务只被分包页面引用。微信开发者工具按文件所在包判断主包资源时，会把这类根目录服务判定为“主包未使用 JS”。
2. `utils/auth.js` 只服务自定义食谱编辑页，放在根 `utils/` 会被主包扫描命中。
3. `app.json` 缺少 `lazyCodeLoading: "requiredComponents"`。
4. 实际打包图片虽然单文件接近 200K 阈值，但开发者工具质量项对图片资源更保守。压缩前 `assets` 图片总量约 906K，扫描仍失败。
5. `.design-check/` 是本地界面检查截图目录，不属于小程序运行资源；该目录已在 `.gitignore` 和 `packOptions.ignore` 中排除，本轮按要求删除其中截图。

## 修复内容

1. 在 `app.json` 增加 `lazyCodeLoading: "requiredComponents"`。
2. 移除根目录只被分包使用的服务文件，将服务下沉到对应分包：
   - `subpackages/custom-recipe/services/customRecipeService.js`
   - `subpackages/custom-recipe/services/recipeAdviceService.js`
   - `subpackages/dog-profile/services/fileService.js`
   - `subpackages/plan-extra/services/customRecipeService.js`
   - `subpackages/plan-extra/services/planCalculatorService.js`
3. 删除根 `utils/auth.js`，在自定义食谱编辑页保留页面内 `requireProfileAuth()` 守卫逻辑。
4. 压缩小程序实际打包图片，`assets` 图片总量降至约 146K。
5. 删除 `.design-check/` 中的临时检查截图，并在 `AGENTS.md` 中补充检查截图清理要求。
6. 更新 `小程序架构设计.md`，同步当前服务层位置、分包边界和登录守卫写法。
7. 补充自动化测试：
   - `app.json` 启用组件按需注入。
   - 小程序图片资源不超过 200K。
   - 算法和建议服务测试改为引用分包内服务入口。

## 验证结果

已运行：

```bash
npm test
find . -name '*.js' -not -path './node_modules/*' -print0 | xargs -0 -n 1 node --check
find . -name '*.json' -not -path './node_modules/*' -print0 | xargs -0 -n 1 node -e "const fs=require('fs'); const file=process.argv[1]; JSON.parse(fs.readFileSync(file,'utf8'))"
find . -type f \( -iname '*.png' -o -iname '*.jpg' -o -iname '*.jpeg' -o -iname '*.gif' -o -iname '*.webp' -o -iname '*.mp3' -o -iname '*.wav' -o -iname '*.m4a' \) -exec sh -c 'for f do size=$(wc -c < "$f"); if [ "$size" -gt 200000 ]; then printf "%8d %s\n" "$size" "$f"; fi; done' sh {} +
```

结果：

- `npm test`：15 项通过。
- JS 语法检查：通过。
- JSON 解析检查：通过。
- 全仓库图片和音频单文件超过 200K 检查：无输出。
- 微信开发者工具本地质量扫描：显示“小程序表现良好，未发现代码质量问题”。

## 后续约定

1. 只在分包使用的页面服务优先放入对应分包，避免进入主包质量扫描。
2. 新增本地检查截图时放入 `.design-check/`，检查结束后删除。
3. 新增设计稿、测试、脚本或文档类文件时，同步评估是否需要加入 `packOptions.ignore`。
